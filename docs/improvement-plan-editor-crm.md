# 관리자 에디터·기본 문구·배포 링크·신청 표시 개선 실행계획

작성일: 2026-09-09
기준 문서: docs/execution-plan.md, docs/adr/003-html-contract-and-sandbox.md, docs/html-template-rules.md

## 1. 배경과 목표

운영자 사용 QA에서 네 가지 문제가 확인됐다. 모두 기존 범위(HTML 등록 → 캠페인 → 배포 → CRM) 안의 결함·UX 개선이며 새 기능 영역을 추가하지 않는다.

| 번호 | 문제 | 성격 |
| --- | --- | --- |
| A | 배포 링크를 매번 버튼으로 만들어야 하고 재방문 시 목록이 비어 있다 | 결함 |
| B | 신청 입력값 상세에서 라디오 제목, 체크박스 값, 셀렉트 한글 텍스트가 잘못 표시된다 | 결함 |
| C | 캠페인 생성 시 등록 HTML의 제목·안내 문구가 기본값으로 채워지지 않는다 | 결함 |
| D | HTML 등록·커스터마이즈를 파일 업로드로만 할 수 있어 진입 장벽이 높다 | 개선 |

작업 순서는 A → B → C → D다. A는 독립적이고 가장 작다. B는 입력 스키마 형태를 바꾸므로 D의 HTML 생성기보다 먼저 확정해야 한다. C는 D의 편집 화면과 같은 데이터 경로를 쓴다.

## 2. A. 4개 채널 링크 즉시 표시

### 현재 동작

`src/components/campaigns/campaign-detail.tsx`는 캠페인만 조회하고 링크는 `loadLinks`를 누를 때만 `POST /api/campaigns/[id]/links`로 가져온다. `ensure_campaign_links`는 이미 멱등이라 링크는 DB에 남아 있지만 화면이 다시 읽지 않아 매번 버튼이 보인다.

### 변경

- `create_campaign_with_form`에서 캠페인 생성 시 4개 채널 링크를 함께 만든다.
- 기존 캠페인 폼에 대한 링크를 채우는 백필을 같은 마이그레이션에 넣는다.
- 읽기 전용 `get_campaign_links(p_campaign_id)`를 추가하고 `GET /api/campaigns/[id]/links`가 이를 호출하게 한다. GET이 쓰기를 수행하지 않도록 분리한다.
- `POST`는 누락 복구용으로 `ensure_campaign_links`를 유지한다.
- 캠페인 상세는 마운트 시 캠페인과 링크를 함께 조회해 4개 링크를 바로 렌더한다. 생성 버튼은 링크 조회가 실패했거나 목록이 비었을 때만 "링크 다시 만들기"로 노출한다.
- 미공개 캠페인에서는 지금처럼 복사 버튼을 비활성 상태로 둔다.

### 검증

- 단위: 링크 목록 응답 정규화 함수.
- 통합: 신규 캠페인 생성 직후 `get_campaign_links`가 4행을 돌려준다. 백필 이후 기존 폼도 4행을 갖는다.
- E2E: 캠페인 상세 최초 진입에서 4개 채널 링크가 버튼 클릭 없이 보인다. 새로고침 후에도 같다.

예상 시간 1시간.

## 3. B. 신청 입력값 표시 정정

### 원인

`src/lib/forms/validate-html.ts`에 세 가지 원인이 있다.

- 라디오 그룹 정규화가 `sameNameFields[0].label`을 그룹 라벨로 쓴다. 첫 번째 선택지의 라벨이 항목 제목 자리에 나온다.
- `optionValues`가 `value` 속성만 모은다. 화면에 사람이 읽을 텍스트가 남지 않아 셀렉트가 `marketing` 같은 원시 값으로 보인다.
- 같은 name을 쓰는 체크박스 그룹이 `DUPLICATE_NAME`으로 거부된다. 체크박스 그룹은 등록 자체가 불가능하다.

표시 단계인 `src/components/campaigns/campaign-insights.tsx`는 값 배열을 그대로 `join(", ")` 한다.

### 변경

- 입력 스키마의 선택지 형태를 `options?: Array<{ value: string; label: string }>`로 바꾼다. 셀렉트는 option 텍스트를 라벨로, value 속성을 값으로 쓴다.
- 라디오·체크박스 그룹의 제목은 래퍼 요소의 `data-form-group-label` 속성에서 읽는다. 속성이 없으면 그룹을 감싼 요소의 첫 텍스트, 그것도 없으면 name을 쓴다. 이 속성을 HTML 작성 규칙, 샘플, AI 프롬프트에 함께 추가한다.
- 같은 name의 체크박스 그룹을 허용한다. 라디오와 같은 정규화 경로를 쓰고 단일 체크박스는 지금처럼 불리언으로 남긴다.
- `src/lib/submissions/validation.ts`는 선택지 값 비교를 `options.map(option => option.value)` 기준으로 하고 체크박스 배열의 각 값도 목록 안에 있는지 검사한다.
- 표시 로직을 `src/lib/submissions/display.ts`로 분리한다. 값 → 라벨 매핑, 배열은 선택한 값만 라벨로 이어 붙이기, 불리언은 예·아니요, 빈 값은 입력 없음으로 처리한다.
- 기존 저장 데이터 호환을 위해 `options`가 문자열 배열인 경우 `{ value, label }`로 읽어 주는 정규화 함수를 두고, `html_templates.input_schema`를 새 형태로 바꾸는 마이그레이션을 함께 넣는다. 저장된 신청 값(JSONB)은 값 그대로 유지하고 표시 시점에만 라벨로 바꾼다.

### 검증

- 단위: 라디오 그룹 제목 추출, 셀렉트 라벨 보존, 체크박스 그룹 허용, 문자열 배열 옵션 하위 호환, 표시 포매터.
- 통합: 마이그레이션 이후 기존 템플릿의 `input_schema`가 새 형태로 읽힌다.
- E2E: 라디오·체크박스·셀렉트를 포함한 샘플로 신청한 뒤 상세에서 그룹 제목과 한글 선택지가 보인다.

예상 시간 3시간.

## 4. C. 등록 HTML의 제목·안내 문구 기본값

### 현재 상태

`GET /api/templates/[id]/preview`는 `extractFormCopy`로 `defaults`를 내려주고 캠페인 생성 화면은 이를 입력값에 채운다. 이 경로는 이미 `main`에 있다. 반면 템플릿 등록 화면에는 제목·안내 문구가 아예 없어 "처음 등록한 값"을 확인하거나 고칠 수 없고, 템플릿 목록 응답에도 문구가 없다.

### 변경

- 먼저 배포본에서 재현한다. 템플릿 선택 시 기본값이 채워지지 않으면 응답의 `defaults` 유무와 마커 텍스트를 확인해 원인을 확정하고 그 결과를 이슈에 남긴다.
- 등록 시 추출한 문구를 `html_templates`의 `default_title`, `default_description`, `default_submit_label` 컬럼에 저장한다. 캠페인 생성 화면이 목록 응답만으로 기본값을 채울 수 있고 Storage를 다시 읽지 않는다.
- 기존 템플릿은 Storage HTML을 다시 파싱해 컬럼을 채우는 백필 스크립트를 둔다.
- 캠페인 생성 화면은 사용자가 직접 고친 항목을 표시해 두고, 템플릿을 바꿀 때 손대지 않은 항목만 새 기본값으로 덮어쓴다. 지금은 입력 중이던 문구가 사라진다.
- 템플릿 상세와 등록 화면에서도 현재 문구를 보여 준다. D의 에디터가 이 값을 그대로 편집 대상으로 쓴다.

### 검증

- 단위: 문구 추출, 미설정 마커의 빈 문자열 처리, 사용자 수정 여부 판단.
- E2E: 템플릿 선택 시 제목·안내 문구가 등록 값으로 채워지고, 문구를 고친 뒤 다른 템플릿을 골라도 고친 값이 유지되는지 확인한다.

예상 시간 1시간.

## 5. D. 관리자 HTML 에디터

### 방향

리치 텍스트 에디터 라이브러리를 도입하지 않는다. 등록 HTML은 허용 목록 계약(ADR-003)을 통과해야 하는데 범용 에디터는 계약 밖 마크업을 자유롭게 만든다. 대신 구조 편집기와 격리 미리보기를 결합한다. 결과 HTML은 앱이 생성하므로 계약 위반이 구조적으로 발생하지 않는다.

### 구성

- `src/lib/forms/document.ts`를 추가한다. `FormDocument` 모델, `parseFormDocument(html)`, `buildFormHtml(document)`를 둔다. 업로드한 HTML은 모델로 파싱해 에디터에 싣고, 저장 시 모델에서 HTML을 만든 뒤 기존 `validateFormHtml`을 통과시킨다.
- 왼쪽 패널에서 제목, 안내 문구, 제출 버튼 문구, 입력 필드 목록(라벨·name·타입·필수·선택지)을 편집한다. 필드 추가·삭제·순서 변경을 지원한다.
- 오른쪽은 현재의 sandbox 미리보기를 유지하되 변경할 때마다 다시 그린다.
- 문구는 미리보기 안에서 직접 고칠 수 있게 한다. `buildEditorTemplate(html, token)`을 추가해 마커 요소에만 `contenteditable`을 부여하고, 공개 폼과 같은 방식의 일회성 토큰 브리지로 편집 결과를 부모에 전달한다. iframe에는 `allow-scripts`만 주고 `allow-same-origin`은 주지 않는다. 부모는 `event.source`와 토큰을 모두 검사한다.
- HTML 직접 편집 탭을 둔다. 검증 오류는 지금처럼 항목별로 표시한다. 파일 업로드 경로는 그대로 남긴다.
- 이미 등록된 템플릿은 덮어쓰지 않는다. 실행계획 5절대로 기존 캠페인의 입력 필드가 바뀌는 것을 막기 위해 상세 화면에는 "복제해 새 템플릿 만들기"만 제공한다.

### 검증

- 단위: 파싱과 생성의 왕복 동등성, 생성 HTML이 `validateFormHtml`을 통과하는지, 지원하지 않는 입력 타입 거부, 에디터 브리지 스크립트 주입 내용.
- E2E: 에디터만으로 템플릿을 만들어 등록하고, 그 템플릿으로 캠페인을 만들어 공개 폼에서 신청까지 완료한다.
- 보안: 에디터 iframe이 동일 출처 권한을 받지 않고 토큰 불일치 메시지를 무시하는지 확인한다.

예상 시간 5시간.

## 8. 위험

- 입력 스키마 형태 변경은 기존 템플릿과 저장된 신청 값에 영향을 준다. 읽기 측 하위 호환 함수와 마이그레이션을 함께 넣고 통합 테스트로 확인한다.
- 링크 생성을 캠페인 생성 시점으로 옮기면 기존 데이터에 공백이 생긴다. 백필을 같은 마이그레이션에 포함한다.
- 에디터 미리보기에 스크립트 권한을 주는 것은 공개 폼과 같은 수준의 위험이다. 동일 출처 권한 미부여와 토큰 검사를 코드 리뷰 항목으로 명시한다.
