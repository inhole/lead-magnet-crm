# ADR-008: 템플릿 등록은 파일 업로드 단일 경로를 유지

- 상태: 채택
- 날짜: 2026-09-10
- 도입: 이슈 #36, PR #37. 되돌린 대상은 이슈 #34, PR #35다.
- 구현: `src/app/templates/new/page.tsx`, `src/components/forms/html-upload.tsx`
- 관련 ADR: [ADR-003](003-html-contract-and-sandbox.md), [ADR-007](007-ui-library-and-states.md)

## 결정

운영자가 HTML을 등록하는 경로는 파일 업로드 하나로 유지한다. 관리자 화면 안에서 입력 필드를 처음부터 구성하는 구조 편집기와 HTML 직접 입력 탭은 제공하지 않는다. 캠페인 생성 화면의 커스터마이즈 범위는 제목, 안내 문구, 제출 버튼 문구 세 가지로 한정한다.

## 이유

구조 편집기를 한 차례 구현한 뒤 되돌렸다. 운영자가 기대한 동작은 업로드한 파일의 미리보기에서 문구를 바로 고치는 것이었는데, 실제로 만들어진 것은 필드를 새로 만드는 별도 폼 빌더와 HTML 텍스트 입력 탭이었다. 등록 화면이 두 갈래로 늘어나면서 원래 흐름인 AI 생성 HTML 등록이 오히려 묻혔다.

범용 폼 빌더는 과제 범위 밖으로 명시되어 있다. 등록 경로가 하나면 [ADR-003](003-html-contract-and-sandbox.md)의 허용 목록 검증도 한 지점에서만 통과하면 되므로 격리 경계를 확인하기 쉽다.

## 영향

- 운영자는 AI로 만든 `.html` 파일을 업로드해야 하며 화면에서 폼 구조를 편집할 수 없다.
- 문구 기본값은 등록 시 추출해 `html_templates`의 문구 컬럼에 저장하고 캠페인 생성 화면이 이를 채운다.
- 미리보기 안에서 문구를 직접 편집하는 개선은 별도 이슈에서 다룬다. 이 결정은 그 방향을 막지 않는다.
